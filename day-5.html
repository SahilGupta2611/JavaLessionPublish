Your destination today

Build a running banking API skeleton and understand why it starts. You should be able to explain Spring versus Spring Boot, read a Maven project, locate configuration, and trace a request into your first endpoint. Allow 2–3 hours, including installation and troubleshooting.

Prerequisites: Days 1–3 Java foundations and Day 4 HTTP/JSON. You know a class is a blueprint and a request is method + URL + headers + body. Today adds a running server; it does not yet add a database, login, or real transfers.

1. What problem does Spring solve?

Suppose a controller needs an account service, the service needs a repository, and a transfer service needs both a repository and a validator. Without a framework, you must construct every dependency, decide lifetimes, configure HTTP routing, parse JSON, and wire errors. That work is repetitive and easy to get wrong.

Spring Framework provides infrastructure such as dependency injection, web request handling, transaction support, and integration utilities. Spring Boot builds on Spring with conventions, starter dependencies, auto-configuration, an application launcher, and embedded-server support. Spring is the toolkit; Boot provides a practical configured starting point.

React comparison: React is the UI library; a project setup gives you a build tool, development server, and conventions. Spring Boot similarly reduces setup, but its application runs on the backend JVM. The analogy is about project infrastructure, not identical runtime behavior.

Boot does not remove your responsibility to design APIs or enforce banking rules. It can configure JSON handling when web dependencies are present. It cannot invent your overdraft rules or ownership checks.

2. The IoC container, gently

IoC means Inversion of Control. Rather than your code constructing every collaborator, Spring creates and connects selected objects. Its application context/container is a registry and lifecycle manager for those objects. A bean is an object managed by that container.

You declare: AccountController needs AccountService.
Spring finds: a suitable AccountService bean.
Spring constructs: AccountController(service).
Requests later use that already-connected controller.

An ordinary new Account(...) domain value need not be a bean. Controllers, services, and repositories often are beans. Most discovered application beans are singleton-scoped by default: one instance per application context. Consequently, don't keep “current customer” or request-specific mutable fields on a shared controller. Two requests can arrive at the same instance.

Day 2 constructor injection is the foundation. The constructor states required collaborators. Day 8 will implement the whole chain; today you only need to understand why annotated classes can be discovered.

3. Choose a reproducible learning setup

The examples in Days 5–9 target Java 21 and Spring Boot 3.5.16, using Spring MVC and jakarta.validation. This pinned course baseline avoids mixing Boot 3 and Boot 4 starter/Jackson changes. It is a learning choice, not a claim that it is the newest release. If Initializr no longer offers that line, generate a current project and deliberately adapt its dependencies, or use the pinned pom below. Do not silently mix examples from different major versions.

Install a JDK 21, not just a runtime. A JDK includes javac, the compiler. Check both commands:

java -version
javac -version

Both should identify Java 21. Your IDE's project JDK and terminal JAVA_HOME can differ. Set the project SDK to the same JDK. You can use IntelliJ IDEA, Eclipse, or VS Code with Java support. The generated Maven wrapper removes the need for a separately installed Maven.

4. Spring Initializr: dependency selection is architectural

Open Spring Initializr. Choose Maven, Java, a compatible Spring Boot version, Jar packaging, and Java 21. Use group com.example, artifact banking-api, package com.example.bank. Select Spring Web and Validation. Add DevTools only if you want development restarts.

A group is a project namespace; an artifact is the build's name. The package is your Java namespace. Download and unzip, then open the folder containing pom.xml in the IDE. Avoid opening only src, because the IDE then loses build configuration.

Do not add JPA/PostgreSQL yet. A database starter can trigger datasource auto-configuration that fails without connection details. We will intentionally store practice data in memory until Day 11.

Dependencies are reusable libraries. A starter is a curated group of compatible libraries for a capability. spring-boot-starter-web on the Boot 3 baseline brings Spring MVC, JSON support, and an embedded servlet server. spring-boot-starter-validation supplies Bean Validation support. Maven downloads transitive dependencies too: you do not manually download every jar.

5. Read a complete pom.xml

<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">
  <modelVersion>4.0.0</modelVersion>
  <parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>3.5.16</version>
    <relativePath/>
  </parent>
  <groupId>com.example</groupId>
  <artifactId>banking-api</artifactId>
  <version>0.0.1-SNAPSHOT</version>
  <properties>
    <java.version>21</java.version>
  </properties>
  <dependencies>
    <dependency>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-web</artifactId>
    </dependency>
    <dependency>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-validation</artifactId>
    </dependency>
    <dependency>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-test</artifactId>
      <scope>test</scope>
    </dependency>
  </dependencies>
  <build>
    <plugins>
      <plugin>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-maven-plugin</artifactId>
      </plugin>
    </plugins>
  </build>
</project>

modelVersion is the Maven model version, not your Java version. The Boot parent supplies compatible dependency versions and build defaults. Your group/artifact/version identifies your application. java.version chooses the intended Java level; it does not install a JDK. A dependency is identified by group and artifact; Boot manages starter versions here. scope=test excludes test libraries from normal application runtime. The Boot Maven plugin packages an executable jar and supports spring-boot:run.

Think pom.xml as the Java build/dependency counterpart of package.json, with different conventions. Maven has a lifecycle: compile compiles source; test compiles and runs tests; package also creates a jar; verify runs later verification phases. clean removes generated build output. Downloading dependencies requires network access the first time.

6. Project and package structure

banking-api/
  pom.xml
  mvnw                     # wrapper for macOS/Linux
  mvnw.cmd                 # wrapper for Windows
  .mvn/wrapper/
  src/main/java/com/example/bank/
    BankingApplication.java
    controller/BankInfoController.java
  src/main/resources/
    application.properties
  src/test/java/com/example/bank/
    BankingApplicationTests.java
  target/                  # generated; don't hand-edit

src/main/java contains Java source. src/main/resources contains runtime configuration/resources. src/test/java is test code. Java package names correspond to directory paths. Public class BankingApplication goes in BankingApplication.java. The main class should be in a root package above controllers/services, so component scanning can discover subpackages. A controller in unrelated other.package may never become a bean.

Later we add service, repository, domain, and dto under com.example.bank. This course uses layers for clarity; real teams may group by feature. Consistent boundaries matter more than a single universal folder layout.

7. The main class, line by line

package com.example.bank;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class BankingApplication {
    public static void main(String[] args) {
        SpringApplication.run(BankingApplication.class, args);
    }
}

package declares the namespace. Imports let us use short type names. @SpringBootApplication combines Boot configuration, auto-configuration, and component scanning. It is metadata interpreted by the framework, not a method call. public static void main is the JVM entry point. String[] args receives command-line arguments. SpringApplication.run creates/configures the application context and starts the application. The class reference tells Boot where application configuration begins.

Auto-configuration is conditional: Boot considers libraries on the classpath, properties, and beans you supplied. It configures common defaults when appropriate. It is not “scan the internet and choose code.” Read startup failures and configuration rather than treating it as magic.

8. Your first banking endpoint

Create src/main/java/com/example/bank/controller/BankInfoController.java:

package com.example.bank.controller;

import java.util.Map;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class BankInfoController {
    @GetMapping("/api/bank-info")
    public Map<String, String> info() {
        return Map.of("name", "Learning Bank", "status", "READY");
    }
}

@RestController registers a web controller and makes return values response bodies. @GetMapping connects GET requests for a path to this method. Map<String,String> is a Java map, not JSON text; Spring uses an HTTP message converter to serialize it. Map.of creates a small unmodifiable map. Day 6 replaces arbitrary maps with typed response models.

GET /api/bank-info HTTP/1.1
Host: localhost:8080
Accept: application/json

HTTP/1.1 200 OK
Content-Type: application/json

{"name":"Learning Bank","status":"READY"}

JSON property order is not a contract. Do not test success by the exact string ordering. This endpoint is a learning info endpoint, not a full production health check.

9. Starting and packaging

From the folder containing pom.xml:

# macOS/Linux (make wrapper executable if needed)
chmod +x mvnw
./mvnw spring-boot:run

# Windows PowerShell
.\mvnw.cmd spring-boot:run

Use the command for your operating system. Stop the process with Ctrl+C. Alternatively run the main class from the IDE. Do not start both simultaneously on the same port.

curl -i http://localhost:8080/api/bank-info

-i displays headers and status along with the body. A browser address bar also sends a GET. To package instead of running in development:

./mvnw clean package
java -jar target/banking-api-0.0.1-SNAPSHOT.jar

The jar contains your application plus necessary dependencies. Its embedded server means you can run it without separately installing Tomcat. Spring Boot is the server-side application; GitHub Pages serves this course's static HTML only and cannot run the banking JVM backend.

10. What happens during startup?

  1. The JVM calls main.
  2. Boot reads configuration and establishes the application context.
  3. Component scanning discovers eligible annotated classes under the root package.
  4. Auto-configuration supplies suitable infrastructure, including MVC and the server for this baseline.
  5. Spring constructs beans and resolves their dependencies.
  6. Web mappings are registered and the embedded server binds its port.
  7. A “Started BankingApplication” message indicates startup finished; then requests can arrive.

A successful build is not the same as a successful server startup. An application can compile while failing to bind its port. A running server is not proof the intended route exists. Verify the endpoint's status and body.

11. Configuration: properties and YAML

Create src/main/resources/application.properties:

spring.application.name=banking-api
server.port=8080

Properties use key=value. A YAML alternative expresses hierarchical keys:

spring:
  application:
    name: banking-api
server:
  port: 8080

Use one format for the same settings while learning; putting conflicting values in both files is confusing. YAML indentation is meaningful; use spaces. server.port=8081 changes where the server listens, so your browser URL must change too. These are backend server ports, independent of the React dev server port.

Profiles select environment-specific configuration. application-dev.properties can contain server.port=8081; activate it with:

./mvnw spring-boot:run -Dspring-boot.run.profiles=dev

Or run a packaged jar with --spring.profiles.active=dev. A profile is a configuration choice, not a security boundary. Never commit credentials in a production profile. Later deployment lessons will use environment variables and secret management. Command-line options can override file settings, so inspect how the app was started when a value seems ignored.

12. Annotation overview and beans

Annotation Typical role Beginner interpretation
@Component Generic managed collaborator Spring should discover this class
@Service Business behavior This component coordinates rules
@Repository Data access This component stores/loads data
@RestController HTTP adapter This component receives API requests

The specialized annotations communicate intent. @Repository also participates in persistence exception translation where applicable. They do not automatically implement methods, create database tables, or validate every rule. Only discovered or explicitly registered objects become beans.

Optional DevTools provides development conveniences such as restart support. It is not required to understand startup and should not be treated as production infrastructure. IDE recompilation and resource changes influence when restart occurs. If a change seems absent, stop, rebuild, and run once to remove uncertainty.

13. Troubleshooting like a backend developer

Symptom Likely cause First useful check
Port already in use Another process owns 8080 Stop other app or use 8081
Unsupported class version / invalid release JDK mismatch Check terminal and IDE JDK
404 from running server Wrong URL or controller not scanned Check mapping and package
Datasource configuration failed Added database starter too early Remove it until Day 11
Dependency resolution failed Network/repository/version problem Read Maven error coordinates
No qualifying bean Missing discovery/implementation Check package and annotations
Whitelabel page at / No root route Try /api/bank-info

Read the first meaningful cause in the stack trace, not only its final line. Avoid random annotation additions. A 404 proves an HTTP server responded; “connection refused” means your client could not connect at that host/port.

14. Why this matters in real work

A teammate should be able to clone, build, and run the same application. Pinning a coherent Java/Boot baseline, keeping generated files separate, and understanding configuration prevents “works on my machine” drift. Component scanning and bean lifetimes explain many runtime problems that Java compilation cannot catch. You now have a place where the HTTP contracts from Day 4 can execute.

15. Hands-on lab: banking skeleton

  1. Create the project and verify the JDK.
  2. Add the main class and BankInfoController exactly under the root package.
  3. Start it and capture the 200 response using curl or Postman.
  4. Add GET /api/welcome returning {"message":"Welcome to Learning Bank"}.
  5. Change the development profile to port 8081 and verify both startup logs and the new URL.
  6. Stop, package, and run the jar. Verify the endpoint again.
  7. Write a README with prerequisites, run commands, profile activation, and endpoint URL.

Acceptance criteria: a fresh checkout has a reproducible build; a documented command starts it; both routes return JSON; no database is required; the profile actually changes the listening port. If you see 404, distinguish route failure from connection failure before editing code.

Challenge: deliberately move the controller outside the root package, observe the 404, then restore it. Explain why it compiled successfully but was not registered as a controller. Add a second small controller in a sibling subpackage to prove your explanation.

16. Knowledge check

1. Is every Java object a Spring bean?

No. Beans are container-managed objects. Domain values you construct yourself normally remain ordinary Java objects.

2. What does a starter provide?

A curated dependency set for a capability, with compatible versions managed by the Boot setup.

3. Why put the main class above controllers?

Its package provides the default component-scan boundary. Subpackages are discovered; unrelated packages may not be.

4. Does changing java.version install Java?

No. It configures the build target. You still need a compatible installed JDK and IDE setup.

5. How are 404 and connection refused different?

404 is a server response for a missing route/resource. Connection refused happens before an HTTP response is available.

6. Can a singleton controller store the active customer's ID in a field?

No. Shared mutable request state can leak across concurrent requests. Keep request values local and derive identity from the request's security context later.

17. Cheat sheet

Spring = infrastructure. Boot = configured application starting point. Bean = managed object. pom.xml declares the build. @SpringBootApplication starts configuration and discovery. Put controllers under its package. Web starter + mapping gives you HTTP routes. Properties configure ports/profiles. Compile, start, and verify are separate steps.
